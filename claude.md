# PROJECT PRINCIPLES

This is a software project where clarity, simplicity and consistency are the top priorities.

---
# PROJECT STRUCTURE

This is a monorepo.

- /frontend → frontend rules apply
- /backend → backend rules apply
---

# GENERAL RULES

- Avoid put comments in code
- Keep solutions simple and practical
- Do NOT overengineer
- Prefer readability over cleverness
- Always follow existing patterns in the codebase
- Do NOT introduce new libraries or patterns unless explicitly requested


---

# CONSISTENCY

- Match the style of existing code
- Reuse existing approaches whenever possible
- Do NOT invent new structures or abstractions

---

# SEPARATION OF CONCERNS

- Respect boundaries between different parts of the application
- Do NOT mix responsibilities
- Keep logic where it belongs

---

# CODING STYLE

- Write clean, readable and maintainable code
- Keep functions small and focused
- Avoid deeply nested logic
- Avoid unnecessary abstractions

---

# FORBIDDEN

- Do NOT add unnecessary dependencies
- Do NOT duplicate logic
- Do NOT create overly large or complex files

---

# BEFORE CODING

- Analyze the existing code
- Follow the same patterns already in use
- If something is unclear, ASK instead of guessing

---

# OUTPUT STYLE

- Provide practical, ready-to-use code
- Keep explanations concise
- Use step-by-step only when useful

---

# ERROR HANDLING

- Prefer simple and predictable solutions
- Avoid handling edge cases unless they are relevant

---

# GOAL

The goal is to build a clean, maintainable and scalable project.

Avoid unnecessary complexity at all costs.
